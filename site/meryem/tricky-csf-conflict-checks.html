Tricky CSF Conflict Checks

By Měryem al Ixbilǐa
meryemsca@gmail.com

Published 21 September 2026
Updated 22 September 2026

This is less a fully-fledged article and more a demonstration of how I do conflict checks, with particular attention to the tricky cases I had to work out the logic of myself. I hope it’s helpful!

I’m writing for readers who are familiar with charge group theory, SENA’s conflict rules, how armory is coded in the O&A, and using the complex search form to eliminate anything with an SC or multiple DCs from the item you’re checking. This is the method of conflict-checking described in Beatrice Domenici della Campana’s complex search conflict checking class and Marie de Blois’s handout on conflict checking with the Complex Search Form. I learned to use the complex search form from Beatrice (by taking her class and asking a lot of follow-up questions while I did an absurd amount of conflict checks), so if you’re familiar with her approach, you’ll understand what I’m doing.

Mixed-Tincture, Two Primary Charges

Consider the armory Azure, in pale a plate and a bezant. How would this be coded?

  • AZ
  • FIELD:azure:solid
  • ROUNDEL:2:g2pa:multicolor light:pl:unc:~ argent:~and or (I believe order doesn’t matter here)
  • INPALE:2:g2pa:multicolor light:~ argent:~and or

What changes can we make to this armory, how much difference would they be worth, and how can we code for them?

  • The field: a divided field is an SC and changing the tincture or removing the field is a DC, so code the first line as AZ. Also add a +0 line at the end with FIELD:solid|NO.
  • The type: anything other than ROUNDEL or ROUNDEL-DEMI would be an SC for type, so we only need to check ROUNDEL and ROUNDEL-DEMI.
  • The number: anything other than 2 primary charges would be an SC for number, and anything other than 2 roundels would be a DC for type. Code the number as ROUNDEL:2:primary|ROUNDEL-DEMI:2:primary.
  • The edge style: I rarely bother coding this for roundels because they’re nearly all plain-line, but it’s not incorrect to code as pl or plain line.
  • The arrangement: similarly, I only bother coding for arrangement if there are too many results, but the arrangement can be coded as INPALE.
  • Whether there are other charges on the field: this can be coded as gpa, and in particular g2pa, because the presence of secondary or overall charges is a DC, and if the primary group didn’t have 2 charges, that would be an SC.
  • The tincture: if we changed the tincture of either roundel, that would be a DC for tincture, and if we divided a roundel to make it multicolor, that would be a DC for tincture—so we can just code it as multicolor light, right? Well, no, because Azure, in pale a crescent argent and a bezant only has a DC for type, but the primary charges would be coded as CRESCENT:1:argent:g2pa:upright and ROUNDEL:1:or:g2pa:pl:unc. If we code for 2 roundels and multicolor roundels, this gives us 2 points off when we only should get one. We can solve this problem by checking the tincture as Or, argent, or multicolor, because if it’s not any of those there’s definitely a DC for tincture: 2 roundels with a different tincture, or one roundel and one other charge, with a roundel of a tincture that is neither argent nor Or. (You could safely code the multicolor tincture as multicolor light, because multicolor neutral/dark would require changing the tincture of a roundel or dividing a roundel, but that’s usually too much overhead for me.)

Taking all of this into consideration, this is how I’d code the complex search:

  • AZ
  • ROUNDEL:2:primary|ROUNDEL-DEMI:2:primary
  • ROUNDEL:multicolor:primary|ROUNDEL-DEMI:multicolor:primary|ROUNDEL:argent:primary|ROUNDEL-DEMI:argent:primary|ROUNDEL:or:primary|ROUNDEL-DEMI:or:primary
  • ROUNDEL:g2pa|ROUNDEL-DEMI:g2pa
  • INPALE:primary
  • +0 FIELD:solid|NO

Three Primary Charges

Now consider Azure, in pale three plates. This would be coded as:

  • AZ
  • FIELD:azure:solid
  • ROUNDEL:3:argent:gpa:pl:unc
  • INPALE:2:g2pa:argent

The considerations for the field, primary type, arrangement, and lack of secondary charges are unchanged. However, the considerations for number and tincture are more complicated.

Comparing to Azure, in pale a lozenge between two roundels, an orle argent, we have a DC for the orle, but we do not have a DC for the type of primary charge, because the lozenge is less than half the charge group and this arrangement does not qualify for any of the exceptions in SENA A5C2d. This means we can’t code the number of roundels as 3, because we’d miss conflicts. To avoid having a problem with this, code the number as 3 or fewer.

Tinctures have the same problem. Azure, in pale a bezant between two plates would have the roundels coded as ROUNDEL:3:g3pa:multicolor light:pl:unc:~ argent:~and or, but there isn’t a DC for tincture. To catch these conflicts, search for roundels that are multicolor as well as argent.

This is how I’d code the complex search:

  • AZ
  • ROUNDEL:3 or fewer:primary|ROUNDEL-DEMI:3 or fewer:primary
  • ROUNDEL:argent:primary|ROUNDEL-DEMI:argent:primary|ROUNDEL:multicolor:primary|ROUNDEL-DEMI:multicolor:primary
  • ROUNDEL:g3pa|ROUNDEL-DEMI:g3pa
  • INPALE:primary
  • +0 FIELD:solid|NO
